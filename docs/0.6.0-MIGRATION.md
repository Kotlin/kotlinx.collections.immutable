# Migration Guide: 0.5.0 to 0.6.0

If your code already uses the new operation names introduced in `0.5.0`, most
call sites need no changes. Check the following cases when upgrading from `0.5.x`.

## Required changes

- **Replace deprecated operation names.** Calls such as `add`, `remove`, `put`,
  and `clear` on persistent collections now produce deprecation errors. Use
  `adding`, `removing`, `putting`, and `cleared` instead. IDE `ReplaceWith`
  quick-fixes are available; see the [full rename table](0.5.0-MIGRATION.md#what-is-renamed).
  Builders and mutable collections keep their imperative names.
- **Update custom implementations.** If you implement `PersistentCollection`,
  `PersistentList`, `PersistentSet`, or `PersistentMap`, override the new functions.
  Overrides of the deprecated functions can be removed. Implementations that
  only override the old functions must be updated and recompiled before use with
  `0.6.0`; otherwise calls to the new functions fail at runtime. See
  [implementation compatibility](0.5.0-MIGRATION.md#implementing-the-interfaces).

## New types

The ordered and unordered flavors are now public interfaces: `PersistentOrderedSet`,
`PersistentUnorderedSet`, `PersistentOrderedMap`, and `PersistentUnorderedMap`, each
with a nested `Builder`. Use them in signatures that need a specific iteration order,
and `persistentOrderedSetOf`, `persistentUnorderedSetOf`, and their map counterparts
to create them. A custom `PersistentSet` or `PersistentMap` can implement a flavor
interface to state its iteration order.

## Set and map conversions

`Iterable.toPersistentSet()` and `Map.toPersistentMap()` now reuse any persistent
receiver, including unordered collections, and call `build()` on corresponding
builders. Previously, unordered inputs were converted to ordered collections.
The same applies to `PersistentCollection.intersect`, which converts the receiver
with `toPersistentSet()`.

If you relied on that conversion to obtain an ordered collection, use
`toPersistentOrderedSet()` or `toPersistentOrderedMap()` explicitly. They preserve
the source's current iteration order and return collections that maintain
insertion order on subsequent updates.

## New deprecation warnings

Hash-named factories and converters remain supported in `0.6.0`, but are deprecated
with warnings. Use the IDE quick-fixes or these equivalent replacements:

| Deprecated | Replacement |
| --- | --- |
| `persistentHashSetOf` | `persistentUnorderedSetOf` |
| `persistentHashMapOf` | `persistentUnorderedMapOf` |
| `toPersistentHashSet` | `toPersistentUnorderedSet` |
| `toPersistentHashMap` | `toPersistentUnorderedMap` |

`persistentSetOf` and `persistentMapOf` still create ordered collections
and keep their existing return types.
